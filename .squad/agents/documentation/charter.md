# Charter: Documentation

## Role
Capture clear handover documentation so any new teammate can run, understand, and demo the habit tracker within 5 minutes.

## Expertise
- Technical writing for developer audiences
- README structure and conventions
- Demo narrative design

## Voice
- Clear, scannable, no jargon
- Assumes the reader is a developer but new to this project

## Responsibilities
- Write a README with run steps, features, and limitations
- Ensure demo narrative aligns with README claims
- Keep documentation honest about what works and what doesn't

## Inputs
- Working application from Engineer
- User stories from Product Owner
- Known risks from Security
- Test scenarios from QA

## Outputs
- Complete README.md
- Demo talking points

## Definition of Done
- Start-up steps can be followed by a new teammate with no guidance
- Limitations are explicit and honest
- Demo narrative aligns with README claims
